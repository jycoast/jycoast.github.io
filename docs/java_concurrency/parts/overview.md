---
title: 什么是并发编程？
---

你写了一段代码，单线程跑得好好的。为了快一点，你把循环拆给几个线程一起干，结果数字对不上了——而且不是每次都错，重启一下又好了。

日志里什么都没有。你盯着代码看了半小时，觉得逻辑上没有任何问题。

这类「诡异」的问题，根源都藏在「并发」两个字里。要搞懂它，得先回答三件事：它在做什么、为什么难、以及用什么框架把它装进去。

### 并发和并行，是两件事

这两个词经常被混着用，但它们说的不是一回事。

想象一个人一边打电话一边记笔记。任何时刻他其实只在做一件事，但他能在两件事之间快速切换，看上去就像同时在处理——**我们把这种「交替推进多个任务」的能力，称为并发（Concurrency）**。

再想象两个人在两个房间里，各自打各自的电话。这一时刻真的有两件事在同时发生，**这种「同一时刻真正同时执行」，称为并行（Parallelism）**。

回到计算机：单核 CPU 也能并发。操作系统把 CPU 的时间切成小片，轮流分给各个线程，切得足够快，看上去就像同时在跑。而并行需要多核——物理上真有不止一块 CPU 在同时执行。

也就是说，并发是一种**结构**——你如何组织任务；并行是一种执行方式——你用多少硬件去跑它。这个区分是后面所有内容的起点，因为它点出了并发出错的真正原因：问题往往不来自「同时在跑」，而来自**切换**——切换发生在哪、切换的那一刻现场是什么状态，决定了结果是两万还是一万三。

### 为什么学习并发编程？

- **它是高性能应用的地基。** 今天撑得住流量的系统，瓶颈几乎都不在单次计算的快慢，而在能不能把等待的时间用起来：CPU 等内存、等磁盘、等网络。把这些等待折叠掉，是性能提升最直接的来源。
- **它是读懂源码的前提。** JUC、Netty、Dubbo、Spring，随便打开一个，并发容器、线程池、异步回调、无锁结构随处可见。不理解并发的语义，源码就只能看个热闹。
- **它是面试的核心区。** 并发能力常被当作「会写代码」和「懂计算机」的分水岭，问得深，也问得细。

### 并发编程难在哪

难不在这几个 API 怎么调，而在于**它要求你同时懂好几个层次的东西**：

1. **知识面跨度大。** 数据结构、计算机组成原理、内存、操作系统、JVM、CPU 微架构都得沾一点，缺哪一块都可能卡住。
2. **底层实现读起来不友好。** 真要追到实现原理，往往要读 C/C++ 甚至汇编，对 Java 程序员是不小的门槛。
3. **概念抽象，缺少锚点。** 例如 happens-before，如果不知道它在解决什么现实问题，背下来也只会一头雾水。
4. **不知道概念从哪来。** 不了解 JSR 的来龙去脉，就不明白 volatile 为什么长成这几个语义。
5. **资料碎，缺一张全景图。** 这一条最要命。以 `synchronized`、`wait()`、`notify()` 为例：孤立地看，它们是一堆琐碎的规则，看懂难，用对更难。可只要往上拉一层——它们**不过是操作系统里管程模型的一种实现**——那些零散的规则立刻有了统一的解释，用起来也就有章法了。

<div class="note info"><p>第 5 条决定了这份知识库的写法：<b>先立模型，再讲实现</b>。管程、内存模型、AQS 都是这样的模型，后面每一篇都会先把模型搭起来，再往下钻。</p></div>

### 怎么学？

一句话概括：**跳出来看全景，钻进去看本质。**

跳出来，是不要「盲人摸象」。并发领域概念太多，一个个孤立地啃，最后只会记住一堆互不相干的术语。先建一张全景图——知道每块知识在解决什么问题、彼此怎么衔接——后面每个点才有地方挂。

钻进去，是不能浅尝辄止。全景不等于理解，关键的点必须下去看：为什么这么设计，不这么设计会怎样。知道怎么用只是入门，知道为什么能这样用才算学会。

<div class="note warning"><p>只有全景没有细节，就成了背概念；只有细节没有全景，就成了背 API。而那张全景图，就是下面这张。</p></div>

### 并发编程的核心问题：分工、同步、互斥

把整个并发领域摊开看，所有概念、关键字、工具类，其实都在回答同样三个问题。用一支团队来对照最容易理解：

| 要解决的问题 | 团队里的说法 | 并发里的说法 |
| --- | --- | --- |
| **分工** | 把大任务拆给几个人，各做各的 | 把任务拆成互不相干的子任务，交给不同线程 |
| **同步** | 我做完了，你才能开始 | 线程之间有依赖，需要等待与通知来协调 |
| **互斥** | 只有一台打印机，谁用谁锁门 | 共享资源必须串行访问，需要加锁保护 |

三个问题，对应三组技术：

- **分工**决定你用什么结构组织任务：线程池、Fork/Join、生产者-消费者。
- **同步**决定线程之间怎么协作：`wait`/`notify`、`Condition`、`CountDownLatch`。
- **互斥**决定怎么保护共享数据：`synchronized`、`Lock`、CAS、无锁结构。

<div class="note info"><p>以后遇到一个没见过的并发概念，先问一句：它是在解决分工、同步，还是互斥？这个习惯能让你在一堆陌生 API 里迅速找到它的位置。</p></div>
